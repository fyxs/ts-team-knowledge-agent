# Agent 开发工作流

## 1. 开始前

1. 阅读 `AGENT.md`、本目录规范和相关 `docs/`。
2. 检查 Git 状态，确认没有覆盖未提交修改。
3. 明确任务范围、输入输出和验收标准。
4. 判断能否复用已有模块，避免重复实现。

## 2. 实现

1. 采用小步、可回滚的修改。
2. 新行为先写测试并确认测试能捕获缺陷，再写最小实现。
3. CLI、API 和 Worker 只调用 application services。
4. 外部工具通过 adapters 接入，持久化通过 repositories 接入。
5. 不修改用户原始素材，不把团队知识内容复制进代码仓。

## 3. 验证

至少执行适用的：

- Python 编译/类型检查；
- 前端 typecheck/build；
- 单元和集成测试；
- Git diff 检查；
- 配置和路径边界检查。

验证失败必须如实报告，不得以部分成功替代完整成功。

## 4. 提交

### 提交信息

- **使用中文描述**。摘要一行说清"做了什么能力或规则的改动"。
- 摘要用动词开头，不写文件名流水账，结尾不加句号。
- 避免"更新""修改""优化"这类无信息量的词；要写出改动带来的具体变化。
- 一次提交只做一件事；混入无关改动时拆开提交，或在正文里说清范围。

示例：

```text
新增历史会话面板并抽出会话状态

- 会话列表支持搜索、切换、新建与相对时间
- 会话状态拆到 useSessions，数据暂用 api/sessions.ts 静态种子
- 同步更新前端结构文档、token 表与路线图
```

### 提交前确认


- 变更只在任务范围内；
- 没有凭据、临时文件、数据库和日志；
- 文档、测试和代码边界一致；
- Git 状态和提交内容已复核。

未经明确授权不执行 push；执行 push 后回读远程分支 SHA。

### 并行工作时的提交纪律

多个 Agent 可能在同一个工作区并行工作。提交时必须：

- **只 `git add` 自己负责的路径，不要使用 `git add -A`**，
  一次传入大量路径可能因文件正被写入而整体失败（返回 128），逐路径 `git add` 更稳；
  否则会把他人未完成的改动一并提交，造成提交内容与提交信息不符；
- 提交后用 `git show --stat HEAD` 复核本次提交实际包含哪些文件；
- 发现混入他人改动时如实说明，不要悄悄 amend 或重写历史；
- 他人尚未提交的改动不要代为提交，也不要代为清理。


## 5. 规则迭代

发现规范缺失、错误或重复时，先修订 `agent/` 中的权威文件，再继续实现；不要把临时经验塞进入口文件或长期记忆。

## 6. 分支约定

- `main` 为稳定分支，只接受经过验证的合并。
- 日常开发与修复在 `dev` 分支进行，不直接向 `main` 提交。
- 并行开发时从 `dev` 派生工作分支，命名为**当前分支名 + 数字**：`dev-1`、`dev-2`……
  完成后合回 `dev`，由 `dev` 再合入 `main`。
- 提交到 `dev` 前仍须通过第 3 节验证的全部检查。
- 需要进入 `main` 时，先确认验证通过，再由用户确认合并。

## 7. 前端改动的附加要求

1. 先读 `docs/frontend-stack.md`，确认技术栈与依赖纪律。
2. 视觉改动只动 token 与组件样式，不引入新的颜色/间距硬编码。
3. 组件改动必须同步更新或新增测试（vitest + jsdom，不依赖真实后端）。
4. 提交前执行 `pnpm typecheck && pnpm test && pnpm build`，三者全绿才算完成。

## 8. 与本机 DLP 共存

- 读写仓库文本文件优先用 `git show` / Python / Node；不要用 PowerShell 直接读字节或写文件，
  否则会出现「文件看起来损坏」或「写入被回滚但仍显示成功」的假象。
- 发现文件被独占锁定（Permission denied / unable to unlink）时停下来确认占用来源，
  不要删除或覆盖，也不要用 `git update-index --skip-worktree` 长期绕过——那只是临时手段，
  恢复后必须解除。

## 9. 并行工作与 worktree

多个 Agent 同时开发时，用 `git worktree` 隔离工作区，避免共用文件树造成的混提交与互相覆盖。

### 工作区

```bash
git worktree add ../<repo>-<n> <branch>     # 新增并行工作区
git worktree list                            # 查看现有工作区
```

只在确实需要并行时创建；单线开发仍在主工作区进行。

### 分支

- 基线分支 `dev`；并行分支按**当前分支名 + 数字**命名：`dev-1`、`dev-2`……
- 同一个分支不能同时检出到两个 worktree，因此并行 Agent 必须使用不同分支。
- 各并行分支完成后合回 `dev`；`dev` 验证通过后再合入 `main`。

### 环境

- 前端依赖各自安装，或用 junction 共享主工作区的 `node_modules`。
- 后端复用同一 `.venv`，用 `PYTHONPATH` 指向各自 worktree 的 `backend`。
- 在 worktree 中启动服务必须换端口（主工作区默认 8088），避免与在用服务冲突。

### 共享运行态

工作目录（配置、SQLite、日志、密钥、知识仓）由所有工作区共用。
扫描与转换由 `RunLock` 保证同一时刻只跑一个，不要绕过它并发执行。

### 边界

- 不提交、不清理、不还原他人未提交的改动。
- 需要迁移或合并他人未提交改动时，先确认对方已停止编辑。
- 修改公共规范（`agent/`、`docs/`）前先确认没有并行改动，避免规则漂移。
